# JobTra AI チュートリアル

この文書は、JobTra を操作する AI がユーザーに説明するための手順です。AI はユーザーの明示的な依頼なしに本文を上書きせず、変更操作の前に対象と変更内容を説明してください。

## 1. 初回利用

1. 「新規作成」を押して下書きを作る。
2. タイトルまたは企業・設問テーマを入力する。
3. 設問カテゴリ、上限字数、進捗を必要なときだけ選ぶ。初期値はすべて未選択です。
4. 本文を入力する。本文欄は入力内容に合わせて広がり、文字数と上限への到達状況が表示される。
5. まず短い例文を入力し、`analyze_writing` で文字数、構成、冗長表現を確認する。

## 2. 下書きの整理・検索

- サイドバーの検索欄では、タイトル、企業名、本文を横断検索できる。
- カテゴリは「すべて」「未分類」「ガクチカ」「志望動機」「自己PR」「困難・挫折」「就活の軸」「入社後」「自由記述」から1つ選べる。
- 「重要」を選ぶと、スターを付けた下書きだけに絞り込める。
- 下書きは作成、選択、複製、スター付け、削除ができる。
- 検索結果の再計算は遅延処理されるため、入力中の操作をブロックしない。

## 3. 執筆エディタ

- 本文はブラウザの IndexedDB に自動保存される。保存状態はヘッダーで確認できる。
- 「フォーカス・センテンス」を有効にすると、カーソルのある一文と文字数を表示する。
- 「タイプライター視線固定」を有効にすると、入力中の行を画面中央付近に保つ。
- 「書式整理」は行末の余分な空白と連続改行を整理する。
- ゴーストガイダンスは、現在の文脈に応じて接続詞や次の一文の候補を示す。AI は候補を説明し、ユーザーの確認なしに確定しない。
- 文章が長すぎる場合は一文の長さ、曖昧表現、過剰敬語、冗長表現などの警告を確認する。
- 削りツールが候補を示した場合は、1件ずつ、または全件を確認して適用できる。

## 4. 問題構成・STAR 構成

1. 下書きバーの「STAR構成」タブを開く。
2. 「結論」「状況・課題」「行動」「成果」「貢献」の各欄に考えを分けて入力する。
3. 構成比率メーターで、行動・成果・貢献に十分な文字数が割かれているか確認する。
4. 「本文エディタへ反映して執筆へ」で、構成を本文へ反映する。
5. 本文へ反映した後は、通常の執筆エディタで文章を自然につなぎ、カテゴリに応じた構成比を再確認する。

## 5. プレビュー・レビュー

- 「プレビュー」タブで、提出前の読み手に近い表示を確認する。
- 提出前チェックリストで、設問への回答、主体性、具体的な数字、誤字、敬語、論理の流れを確認する。
- 推敲ハンドブックでは STAR 法、文字数配分、ビジネス表現、採点基準を読む。
- スナップショットを保存すると、その時点の本文を履歴として残せる。
- 履歴では現在の本文と過去版を比較し、必要なら過去版を復元する。
- AI は `get_writing_context`、`analyze_writing`、`compare_writing_versions` を順番に使い、分析結果を提案として説明する。

## 6. エクスポート・提出

プレビューまたはヘッダーの「エクスポート」を開く。

### Markdown

- `.md` ファイルをダウンロードできる。
- 本文だけでなく、タイトル、企業名、カテゴリ、文字数、作成日などのメタデータを YAML フロントマターに含められる。
- STAR 構成メモと推敲メモ・構成比率を含めるか選べる。
- Markdown をクリップボードへコピーして、企業の応募フォーム、Notion、Obsidian、GitHub などへ貼り付けられる。

### PDF

- ブラウザ内の日本語組版で PDF を生成する。
- 企業名、上限字数、作成日などのメタ情報を含められる。
- STAR 構成メモを含めるか選べる。
- アプリ用サーバーへ本文を送信せず、ブラウザ内で生成する。

### 提出用コピー

「提出用にコピー」は、行末空白や不要な連続改行を整理してクリップボードへコピーする。コピー後に企業の Web フォームへ貼り付け、フォーム側の文字数表示でも確認する。

## 7. QR コードで端末同期

1. ヘッダーの「端末同期」を開く。
2. 送信側で「QRを発行する」を押す。
3. 受信側で「QRを読み取る」を押し、カメラで読み取る。
4. カメラが使えない場合は、表示された一時トークンをコピーして手入力する。
5. 接続中は両方の画面を開いたままにする。
6. 同期完了後、競合があれば各項目について「この端末」か「相手の端末」を選ぶ。

QR の情報は短時間で失効する一時鍵です。本文を同期リレーへ保存せず、接続時だけ WebRTC の DataChannel で送ります。同期後は結果と競合解決を確認してから閉じます。

## 8. 個人 Dexie Cloud 同期

ユーザーが個人 Dexie Cloud の URL を設定している場合、別端末でも同じ URL と同じ認証方法を使う。接続設定がない場合はローカル IndexedDB のみで動作する。設定手順は `get_jobtra_cloud_setup_guide` で取得する。

## 9. WebMCP で実演する

ユーザーが「実際に試して」と依頼した場合は、次の順序で操作する。

1. `get_jobtra_tutorial` で対象ステージの手順を取得する。
2. 現在の下書きと文字数を `get_writing_context` で確認する。
3. ユーザーに入力内容と変更方法を説明する。
4. 明示的な確認を得た場合だけ、`apply_tutorial_example` に `confirm: true` を指定する。
5. 入力結果を `analyze_writing` で評価する。
6. ユーザーが希望した場合だけ、構成・レビュー・エクスポート・同期の次の手順を説明する。

`apply_tutorial_example` は既存本文を勝手に置換しない。分析や比較は読み取り専用であり、本文の正本は JobTra の IndexedDB です。
